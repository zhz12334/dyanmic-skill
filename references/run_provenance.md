# Run Provenance and Evidence Binding

Every evidence-producing run should have a unique run ID and manifest.

## Bind
- code commit/tree hash and dirty diff hash
- source data and paper-target hashes
- configuration/parameter/implementation-contract hashes
- Python/MATLAB/solver/tool versions
- OS and relevant libraries/compilers
- hardware when numerically relevant
- seeds and stochastic policy
- exact command
- timestamps/runtime
- output hashes
- claim metrics/verdicts generated by the run

If any bound artifact changes, previous run evidence is stale until rerun or explicitly grandfathered with justification.
